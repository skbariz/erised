# Batch 3: Architecture Innovations (H581–H590)

## Thesis
Batches 1 and 2 operate within the existing SLSQP+vol-target architecture: find better parameters
(Batch 1) or a better pool (Batch 2). Batch 3 tests fundamentally different architectures that
could break through the H559 ceiling without relying on parameter tuning or pool expansion.

The three architectural ideas to test:
1. **Hierarchical/sleeve optimization** — optimize AA and CS separately, then blend
2. **Joint weight+leverage optimization** — optimize weights AND leverage parameters simultaneously
3. **Global/robust optimization** — differential evolution, bootstrap resampling, correlation-penalized objectives

Each idea has a specific mechanism by which it might improve on H559. The key constraint:
all architectures must use the walk-forward framework without modification — no lookahead.

---

## H581 — Two-Sleeve Hierarchical Lev-Sharpe

**Signal:** Divide the 55-strategy pool into two sleeves: AA (37 strategies, H001-H100) and CS
(18 strategies, cross-sectional). Optimize each sleeve separately with lev-Sharpe objective,
then combine at the portfolio level with a final blend weight w_AA vs w_CS.
**Hypothesis:** H559's joint optimization over 55 strategies may be misallocating between the AA
and CS sleeves because their return structures differ fundamentally. CS strategies have zero-
return folds 0-5 (EDGAR gap); AA strategies have returns in all folds. A joint optimizer may
over-reward AA in folds 0-5 and under-reward CS in folds 6-11. Separate optimization aligns
objectives to the data availability of each sleeve.

**Implementation:**
```python
# Phase 1: optimize AA sleeve
w_aa_opt = slsqp_lev_sharpe(mat_aa)   # 37-strategy submatrix
# Phase 2: optimize CS sleeve (ignoring folds 0-5)
w_cs_opt = slsqp_lev_sharpe(mat_cs, mask=folds_6_to_11)
# Phase 3: blend at portfolio level
r_aa = mat_aa @ w_aa_opt
r_cs = mat_cs @ w_cs_opt
blend_grid = np.linspace(0.4, 0.6, 5)
best_blend = max(blend_grid, key=lambda b: compute_sharpe(apply_vol_leverage(b*r_aa + (1-b)*r_cs)))
r_portfolio = best_blend*r_aa + (1-best_blend)*r_cs
```

**Design note:** Phase 3 blend optimization is done on full OOS (all 12 folds). Because folds
0-5 have r_cs ≈ 0, the blend for those folds effectively sees r_portfolio ≈ best_blend × r_aa.
This naturally reduces CS sleeve weight for the early folds without any explicit fold masking.

**Expected behavior:** CS sleeve should earn 0.2-0.35 portfolio weight (meaningful but controlled).
AA sleeve should dominate early folds; CS adds alpha in folds 6-11.

**Success criteria:** Sh_lev > H559 (1.879) with fold 6 (EDGAR) Sharpe > H559's fold 6 Sharpe.
Specifically looking for improvement in the weak folds. If fold 6 stays the same but Sh_lev
improves, hierarchical structure doesn't solve the EDGAR problem but still adds value.

## H582 — Joint Weight+Leverage Optimization

**Signal:** Instead of fixed leverage parameters with optimized weights, optimize weights AND
leverage parameters (target_vol, cap) simultaneously using SLSQP.
**Hypothesis:** H559 optimizes weights given fixed leverage params (6.5%/2.0×/20d). But different
portfolios have different optimal leverage profiles. A high-CAGR/high-vol portfolio benefits from
lower target_vol (more de-risking in volatile periods); a low-vol consistent portfolio benefits
from higher target_vol. Joint optimization finds the portfolio-leverage pair that globally
maximizes leveraged Sharpe.

**Implementation:**
```python
def neg_joint_lev_sharpe(params):
    n = len(strategy_names)
    w = params[:n]
    target_vol = params[n]      # leverage param 1
    cap = params[n+1]           # leverage param 2
    # normalize weights
    w = np.maximum(w, 0)
    w = w / w.sum()
    r_base = mat @ w
    r_lev = apply_vol_leverage_params(r_base, target_vol, cap)
    return -compute_sharpe(r_lev)

# Bounds: weights [0,1], target_vol [0.04, 0.10], cap [1.5, 3.0]
# Warm-start: H559 weights + 0.065 + 2.0
```

**Risk:** Adding 2 continuous parameters to a 55-dimensional optimization increases the search
space substantially. SLSQP's gradient-based approach may find local optima more easily. Mitigate
by running 5 random restarts plus the MDR warm-start, selecting best result.

**Expected outcome:** The joint optimizer will likely find (target_vol, cap) that differs from
(6.5%, 2.0×). If it finds target_vol=5.5% and cap=2.5×, the portfolio concentrates differently
than H559. The test is whether joint optimization beats Batch 1's best separate parameter solution.

**Success criteria:** Sh_lev > max(H559, best Batch 1 result). Falsification: joint optimization
converges to approximately H559's solution → the objective surface is smooth around (6.5%, 2.0×).

## H583 — Differential Evolution Ensemble

**Signal:** Use scipy.optimize.differential_evolution (global search) instead of SLSQP (local
search) to find the lev-Sharpe-optimal weights.
**Hypothesis:** SLSQP with MDR warm-start may be finding a local optimum that MDR "funnels" it
toward. MDR concentrates on uncorrelated strategies; the lev-Sharpe optimizer then perturbs these
weights slightly. Differential evolution is a population-based global optimizer that explores the
full weight space without being anchored to MDR.

**Implementation:**
```python
from scipy.optimize import differential_evolution

result = differential_evolution(
    neg_lev_sharpe_with_constraint,
    bounds=[(0, 1)] * n_strategies,
    maxiter=1000,
    tol=1e-6,
    seed=42,
    workers=-1  # parallel evaluation
)
```

**Constraint handling:** DE doesn't natively support equality constraints. Implement sum-to-1
via reparameterization: use n-1 free weights, compute last as 1-sum(others), project negatives
to zero then renormalize. Or use penalty method: add large penalty for sum ≠ 1.

**Runtime concern:** DE is much slower than SLSQP. At 1000 iterations with population=15×55=825
individuals, each iteration evaluates the objective 825 times. Estimate: 1000 × 825 × (cost of
lev_sharpe eval) ≈ 30-60 minutes per fold, × 12 folds = 6-12 hours. Run with `workers=-1`
for parallel evaluation.

**Success criteria:** DE result > H559 (1.879) by > 0.05 Sharpe = strong evidence SLSQP was
at local optima. If DE matches H559 ±0.03, SLSQP's MDR warm-start is finding the global optimum.

## H584 — H001-Corr-Penalized Lev-Sharpe

**Signal:** Lev-Sharpe SLSQP with an explicit H001 correlation penalty: maximize
Sh_lev - λ × corr(portfolio_returns, H001_returns).
**Hypothesis:** H559 achieves H001 corr +0.451, down from H556's +0.612. But +0.451 is still
high — the portfolio remains significantly correlated with the US equity market. Adding an
explicit correlation penalty to the objective should force the optimizer to find a lower-H001-
corr ensemble that still maintains high leveraged Sharpe.

**Why this matters:** For an institutional investor, a portfolio correlated +0.45 with SPY
provides limited diversification benefit. A portfolio at +0.25 H001 corr with Sh 1.75 may be
more valuable than +0.45 corr with Sh 1.879.

**Implementation:**
```python
def neg_penalized_lev_sharpe(w, lambda_corr=0.5):
    r_base = mat @ w
    r_lev = apply_vol_leverage(r_base)
    sh_lev = compute_sharpe(r_lev)
    corr_h001 = np.corrcoef(r_lev, h001_returns)[0, 1]
    return -(sh_lev - lambda_corr * corr_h001)

# Sweep lambda_corr in [0.1, 0.3, 0.5, 1.0] to trace corr/Sharpe tradeoff
```

**Expected outcome:** Lambda=0.1 barely reduces H001 corr; lambda=1.0 reduces to ~+0.2 corr
but at ~0.2 Sharpe cost. Find the lambda that achieves H001 corr < 0.30 with Sh_lev > 1.7.

**Success criteria:** H001 corr < 0.30 with Sh_lev > 1.70 (institutional-grade diversification
at near-champion Sharpe). This is a NEW frontier not explored by any prior strategy.

## H585 — Bootstrap-Robust Ensemble

**Signal:** Instead of optimizing on the actual OOS return matrix, bootstrap-resample the OOS
returns N=200 times and optimize on each bootstrap sample. Average the N=200 weight vectors.
**Hypothesis:** H559's SLSQP may be overfit to the specific realization of OOS returns. If the
optimizer finds weights that are unusually good for the observed fold sequence but fragile to
small perturbations, the bootstrap-averaged weights will be more robust.

**Implementation:**
```python
n_bootstrap = 200
all_weights = []
for seed in range(n_bootstrap):
    rng = np.random.RandomState(seed)
    boot_idx = rng.choice(len(r_oos), len(r_oos), replace=True)
    mat_boot = mat[boot_idx]
    w_boot = slsqp_lev_sharpe(mat_boot, warm_start=mdr_weights)
    all_weights.append(w_boot)
w_final = np.mean(all_weights, axis=0)
w_final /= w_final.sum()
```

**Expected behavior:** Bootstrap-averaged weights will be more spread across strategies (less
concentrated than H559's 5-strategy concentration). May have lower peak Sharpe but better worst-
fold Sharpe.

**Success criteria:** Minimum fold Sharpe > H559's minimum (1.157) AND Sh_lev > 1.750. This
is specifically a worst-fold-improving strategy, not a Sharpe-maximizing one.

## H586 — Shrinkage-to-MDR Ensemble

**Signal:** Regularized SLSQP: minimize (neg_lev_sharpe + μ × ||w - w_mdr||²).
Penalizes deviation from MDR solution. Analogous to ridge regression shrinkage toward a prior.
**Hypothesis:** The MDR warm-start in H559 is a single point initialization. Shrinkage regularization
keeps the optimizer anchored near MDR throughout the optimization, preventing wild weight
concentration in strategies that happen to have high lev-Sharpe in the observed OOS.

**Sweep μ in [0.01, 0.1, 0.5, 2.0] to trace the MDR→lev-Sharpe frontier.**

**Expected behavior:** μ=2.0 ≈ MDR weights (Sh_lev ≈ 1.750-1.780); μ=0.01 ≈ H559 (Sh_lev ≈
1.879). The regularization path shows how much of H559's improvement over MDR is "earned" vs
overfit to OOS returns.

**Success criteria:** Find the smallest μ where improvement over MDR plateaus, then check if
that μ value improves H559's OOS Sharpe through robustness.

## H587 — Factor-Risk-Parity Sleeve (Orthogonal Factors)

**Signal:** Decompose the 55-strategy return matrix using PCA into 8-10 orthogonal factors.
Assign equal risk budget to each factor. Reconstruct portfolio weights from factor risk parity.
**Hypothesis:** Standard risk parity (H021) applies equal risk budget to asset classes. Factor
risk parity applies equal risk budget to RETURN FACTORS. In the 55-strategy space, PCA factors
represent: (1) broad equity beta, (2) quality/momentum spread, (3) calendar effects, (4) L/S
reversion, etc. Equal risk parity across these factors should produce a well-diversified ensemble.

**Key difference from MDR:** MDR maximizes diversification ratio (Sharpe of a weighted combination
of Sharpe ratios). Factor risk parity directly balances factor exposure without assuming that
diversification ≡ maximum Sharpe.

**Expected behavior:** Should produce weights more stable across time than SLSQP (no optimization
objective susceptible to overfitting). May have lower peak Sharpe but better OOS stability.

**Success criteria:** Sh_lev > H549 MDR (1.546). If not a program champion, the result informs
the relative value of factor vs MDR diversification.

## H588 — Regime-Adaptive Sleeve Weights (2 regimes)

**Signal:** Two-portfolio system: Portfolio A (H559 weights, lev-Sharpe optimized), Portfolio B
(H552 MDR weights, drawdown-stable). Hold A when SPY > 200d MA; hold B when SPY < 200d MA.
**Hypothesis:** H559 is optimized for bull markets (high CAGR, higher MaxDD). H552 MDR is more
conservative. Switching to MDR in bear markets provides downside protection without abandoning
the H559 champion in bull markets.

**Historical context:** H548 (regime switching on H516 weights) destroyed value (-0.073 Sharpe).
However, H548 switched between UNLEVERAGED portfolios. H588 switches between LEVERAGED portfolios.
The mechanism is different: we're not changing leverage by switching regimes; we're changing the
underlying portfolio's risk profile.

**Risk:** This is a regime-switching overlay. It will be wrong at transitions (false bear signals
in 2011, 2015, 2018 mini-corrections). Each wrong switch costs leverage borrow + trading costs.

**Success criteria:** Sh_lev > H559 (1.879) AND MaxDD_lev < H559 (-9.73%). Both must be better.
If either degrades, regime switching is destroying value as in H548.

**Falsification:** Any degradation vs H559 confirms H548's lesson — regime switching on a mature
ensemble doesn't work.

## H589 — Walk-Forward Weight Re-Optimization (Annual Refit)

**Signal:** H559's weights are OOS (computed from walk-forward training windows, never touching
OOS data). But the weights are FIXED within each test period. This strategy re-optimizes weights
monthly or quarterly within each test fold, using only data available up to the reoptimization date.
**Hypothesis:** The optimal lev-Sharpe weights shift over time. The composition of strategies
that pair well with vol-targeting changes as correlation structures evolve. Monthly reoptimization
should capture these shifts.

**Risk:** Monthly weight reoptimization increases the effective number of optimization decisions
from 12 (one per fold) to ~200 (once per month). This is a massive increase in overfitting
opportunity. Require the improvement to be > 0.05 Sharpe to overcome this concern.

**Implementation:**
- In each 2-year OOS fold (260 trading days), reoptimize weights every 63 trading days
- Each reoptimization uses the 5-year training window preceding the reoptimization date
- Apply new weights from the next trading day

**Success criteria:** Sh_lev > 1.950 (require > 0.07 improvement over H559 given overfitting risk).
Falsification: improvement < 0.03 → fixed weights are already capturing the temporal structure.

## H590 — Ensemble of Ensemble Architectures

**Signal:** Equal-weight blend of 3 portfolios: H559 (lev-Sharpe), H558 (lev-Calmar), and the
best Batch 1 result (H56x best). Apply vol-targeting to the combined portfolio.
**Hypothesis:** H559 and H558 have complementary weight structures: H559 concentrates in H076/H265
(Sharpe-friendly), H558 concentrates in H065/H473 (Calmar-friendly). Combining them creates a
portfolio with more balanced exposure. Applying vol-targeting to the combined portfolio (rather
than to each separately) may produce better risk-adjusted returns than any single approach.

**Implementation:**
```python
r_h559 = mat @ w_h559  # lev-Sharpe weights
r_h558 = mat @ w_h558  # lev-Calmar weights  
r_h56x = mat @ w_best_batch1  # best Batch 1 result
r_ensemble = (r_h559 + r_h558 + r_h56x) / 3
r_leveraged = apply_vol_leverage(r_ensemble)
```

**Expected behavior:** The combined portfolio should have lower MaxDD than H559 (-9.73%) because
H558 acts as a MaxDD buffer, while maintaining Sharpe above H558 (1.697) because H559's higher-
Sharpe weights dominate half the portfolio.

**Success criteria:** Sh_lev > 1.80 AND MaxDD_lev < -8.0% (strictly Pareto-dominates H558 on
both Sharpe and MaxDD, approaching H559 on Sharpe while matching H558 on MaxDD).

## Batch 3 Priority Order

1. **H581** (hierarchical sleeves) — directly addresses the EDGAR fold 6 weakness of H559
2. **H583** (differential evolution) — definitively tests whether H559 is at the global optimum
3. **H584** (H001-corr penalty) — maps a new institutional diversification frontier
4. **H585** (bootstrap robust) — addresses overfitting concern
5. **H582** (joint weight+leverage) — follow only if Batch 1 finds params differ significantly
6. H586, H587, H588, H589, H590 — run after priority ones; H590 is fast (no new optimization)

**Expected batch outcome:** H583 is the most decisive test. If DE matches H559, the architecture
is globally near-optimal and Batch 4 should focus on new strategies (Batch 2 approach). If DE
significantly beats H559, Batch 4 should build a multi-restart SLSQP framework.
