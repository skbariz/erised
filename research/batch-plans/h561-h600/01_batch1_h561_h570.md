# Batch 1: Leverage Parameter Space Exploration (H561–H570)

## Thesis
H559 uses fixed leverage parameters (target_vol=6.5%, cap=2.0×, lookback=20d). These were inherited
from H556 which inherited them from H086's original walk-forward-validated parameters. H559's lev-
Sharpe SLSQP co-adapted weights to THESE parameters. The question: are 6.5%/2.0×/20d globally
optimal, or did H559 merely find the best weights for locally suboptimal leverage parameters?

---

## H561 — LeverageParamGridSearch

**Signal:** Lev-Sharpe objective (H559's winner) over a 3-D grid of leverage parameters.
**Hypothesis:** The target_vol=6.5% was chosen because 6.5% ≈ SPY realized vol in bull markets.
A slightly higher target (8%, matching H086's original) or a shorter lookback (10d instead of 20d)
may produce better Sharpe by capturing faster vol regimes.

**Parameter grid:**
```
target_vol:  [5.0%, 6.5%, 8.0%]
cap:         [1.5×, 2.0×, 3.0×]
lookback:    [10, 20, 40]  (days)
```
Run lev-Sharpe SLSQP on full-55 pool with MDR warm-start for each combination (27 runs).
Report Sh_lev, Cal_lev, MaxDD_lev, CAGR_lev, avg_leverage for each. Best by Sh_lev.

**Expected behavior:** Shorter lookback (10d) should react faster to vol spikes → better post-
spike recovery. Higher cap (3.0×) should improve CAGR in low-vol periods but worsen MaxDD.

**Success criteria:** Any parameter combo improves on H559's 1.879 Sharpe. Improvement > 0.05
Sharpe = high confidence the original params were suboptimal.

**Falsification:** Grid shows 6.5%/2.0×/20d is within ±0.03 Sharpe of the optimum across
all combinations → original params were robust, not just lucky.

**Bias checks:**
- The SLSQP re-optimizes weights for each parameter set — no lookahead; each weight solution
  is derived entirely on OOS returns (cross-sectional window by window in walk-forward).
- Parameter selection uses held-in performance across all 12 folds → mild overfitting risk.
  Mitigate by requiring best > H559 by ≥ 0.05 Sharpe before declaring a new champion.
- Do NOT use holdout data for this search.

## H562 — HighCapLeveragedSharpe (cap=3.0×, target_vol=5.0%)

**Signal:** Lev-Sharpe SLSQP with aggressive leverage: target_vol=5.0%, cap=3.0×, lookback=20d.
**Hypothesis:** H559's avg realized leverage was only 1.23×, far below the 2.0× cap. At 2.0×
cap, the leverage mechanism rarely reaches its maximum. Raising the cap to 3.0× and lowering
target_vol to 5% would push avg realized leverage to ~1.6-1.8× in low-vol periods, substantially
increasing CAGR.

**Expected outcome:** CAGR should exceed H559's 13.08% (perhaps 15-18%). Sharpe may improve or
stay flat depending on whether higher leverage adds more return than risk. MaxDD should worsen
(perhaps -13 to -15%) but remain below SPY's -55%.

**Implementation:**
```python
def apply_vol_leverage_aggressive(r_arr):
    r = pd.Series(r_arr)
    rv = r.rolling(20).std().shift(1) * sqrt(252)
    lev = (0.05 / rv).clip(upper=3.0)
    borrow = (lev - 1).clip(0) * 0.005 / 252
    return (lev * r - borrow).values
```

**Success criteria:** Sh_lev > 1.879 (beats H559) OR CAGR > 15% at Sh_lev > 1.7.
**Falsification:** Higher cap adds leverage without improving Sharpe (more risk than return).

## H563 — FastVolLookbackSharpe (lookback=5d)

**Signal:** Lev-Sharpe SLSQP with ultra-fast vol lookback: target_vol=6.5%, cap=2.0×, lookback=5d.
**Hypothesis:** H559 uses 20d lookback — a relatively slow estimate of realized vol. During
fast-moving events (COVID crash in 20 days, Oct 2008), the 20d lookback lags reality by 1-2
weeks. A 5d lookback de-risks much faster, potentially reducing the "getting caught with high
leverage at peak vol" problem.

**Risk:** 5d lookback is very noisy. It will cause more leverage oscillation day-to-day, potentially
increasing trading costs and reducing Sharpe. The daily borrow cost (0.5% annualized) compounds
when leverage is high and oscillating.

**Implementation:** Same as H559 but `rolling(5)` instead of `rolling(20)`.

**Success criteria:** Sh_lev > H559 (1.879) OR MaxDD_lev < H559 (-9.73%) at Sh_lev > 1.8.
**Falsification:** Fast lookback increases leverage oscillation → higher trading costs → worse
Sharpe than H559.

## H564 — MaxDDConstrainedLevSharpe (DD constraint ≤ 7%)

**Signal:** Lev-Sharpe SLSQP with explicit MaxDD penalty to enforce MaxDD_lev ≤ 7%.
**Hypothesis:** H559's lev-Composite achieves 1.762 Sharpe at -7.25% DD by blending objectives.
But maybe an explicit MaxDD constraint via a penalty term gives better Sharpe-per-DD-unit than
blending equal weights.

**Implementation:**
```python
def neg_penalized_lev_sharpe(w, dd_penalty=10.0):
    r_base = mat @ w
    r_lev = apply_vol_leverage(r_base)
    sh = compute_sharpe(r_lev)
    dd = compute_maxdd(r_lev)  # negative number
    penalty = dd_penalty * max(0, -dd - 0.07)  # penalize DD worse than -7%
    return -(sh - penalty)
```

Sweep dd_penalty in [1.0, 5.0, 10.0, 20.0] to trace the Pareto frontier.

**Success criteria:** Any point on Pareto frontier with Sh_lev > 1.762 and DD_lev < -9.73%
(beats lev-Composite on Sharpe and H559 on MaxDD simultaneously).

## H565 — AsymmetricVolTarget

**Signal:** Asymmetric vol-targeting: fast de-lever when vol is rising (5d lookback), slow re-lever
when vol is falling (40d lookback). This is a one-way ratchet on vol estimation.
**Hypothesis:** Most of the MaxDD damage happens in the first 3-7 days of a crash when vol
explodes. Vol-targeting with a 20d lookback is still 10-15 days late. If we use 5d vol when it's
ABOVE the 20d estimate (and 20d otherwise), we de-risk faster in crashes without adding lookback
noise in calm periods.

**Implementation:**
```python
def apply_asymmetric_vol_leverage(r_arr):
    r = pd.Series(r_arr)
    vol_fast = r.rolling(5).std().shift(1) * sqrt(252)
    vol_slow = r.rolling(20).std().shift(1) * sqrt(252)
    vol_eff = vol_fast.where(vol_fast > vol_slow, vol_slow)  # use max of fast/slow
    lev = (0.065 / vol_eff).clip(upper=2.0)
    borrow = (lev - 1).clip(0) * 0.005 / 252
    return (lev * r - borrow).values
```

**Expected behavior:** Should produce MaxDD between H559 (-9.73%) and Lev-Composite (-7.25%)
while preserving Sharpe closer to H559 (1.879) than Lev-Composite (1.762).

**Success criteria:** Sh_lev > 1.820 AND DD_lev > -8.5% (strictly Pareto-dominates both H559
and lev-Composite along Sharpe/DD tradeoff).

## H566 — LevCAGRObjective

**Signal:** SLSQP maximizing annualized CAGR of vol-targeted portfolio.
**Hypothesis:** H559 maximizes Sharpe (CAGR/vol ratio). H558 maximizes Calmar (CAGR/MaxDD ratio).
What portfolio maximizes raw CAGR under vol-targeting? This should produce the highest possible
CAGR while still using the H556 leverage mechanism as a floor.

**Expected outcome:** Weights concentrate heavily in high-CAGR strategies regardless of vol or
drawdown. H473 (which has high CAGR but also deep drawdowns) should earn large weight. MaxDD
will likely be worse than H559 (-9.73%).

**Success criteria:** CAGR_lev > 16% at Sharpe > 1.5. If not kept, the solution maps the CAGR
frontier and informs Batch 4 terminal champion design.

**Note on overfitting risk:** CAGR is more susceptible to overfitting than Sharpe (no variance
penalty). The CI will be wider and fold variance will be higher. Require CI lower bound > 1.3
AND all-12-folds-positive before declaring KEEP.

## H567 — LevSortino + Explicit DownsideVol Target

**Signal:** Replace vol-targeting with downside-vol targeting: leverage_t = min(2.0, target_downvol /
downside_realized_vol_{t,20d}). Combine with lev-Sortino SLSQP.
**Hypothesis:** Standard vol-targeting scales based on total realized vol, including upside vol.
When a portfolio is rallying strongly (high upside vol), the vol-target de-risks unnecessarily.
If we use DOWNSIDE vol (only daily returns below zero), we only de-risk when the portfolio is
actually losing money.

**Implementation:**
```python
def apply_downside_vol_leverage(r_arr, target=0.065):
    r = pd.Series(r_arr)
    neg_r = r.where(r < 0, 0)
    down_vol = neg_r.rolling(20).std().shift(1) * sqrt(252) * sqrt(2)  # annualize
    lev = (target / down_vol.replace(0, np.nan)).clip(upper=2.0).fillna(1.0)
    borrow = (lev - 1).clip(0) * 0.005 / 252
    return (lev * r - borrow).values
```

**Expected behavior:** In sustained rallies, leverage stays closer to 2.0× longer. In crashes,
de-levers faster because downside vol spikes harder than total vol.

**Success criteria:** Sh_lev > H559 (1.879) OR Calmar_lev > H558 (1.802) at comparable DD.

## H568 — WalkForwardLeverageParams

**Signal:** Treat leverage parameters (target_vol, cap) as hyperparameters optimized in the
walk-forward training window — each fold selects its own optimal params.
**Hypothesis:** The optimal leverage params may shift over regimes. In the 1993-2000 low-vol
period, a higher target (8%) captures more return. In post-2008 high-vol regime, lower target
(5%) reduces drawdown. Walk-forward selection discovers regime-specific optimal params.

**Implementation:**
- In each training fold, sweep 9 (target_vol, cap) combinations and select by Sharpe
- Apply selected params to that fold's OOS window
- Weights are re-optimized for each (params × fold) combination

**Risk:** 9 combinations × 12 folds = 108 parameter selections. HIGH overfitting risk.
Mitigate by using 3×3 grid (5%, 6.5%, 8%) × (1.5×, 2.0×, 3.0×) only; no lookback variation.

**Success criteria:** Walk-forward selected params outperform H559's fixed params by > 0.05
Sharpe. Falsification: WF selection gives < 0.03 Sharpe improvement → fixed params are robust.

## H569 — CostAwareLevSharpe (realistic borrow cost)

**Signal:** Lev-Sharpe objective with realistic time-varying borrow cost (Fed Funds Rate + 50bps).
**Hypothesis:** H559 uses 0.5% annualized flat borrow cost (5bps per 100bps leverage). In
pre-2009 period, Fed Funds Rate was 4-5%, so actual borrow cost for leverage was 5-6%, not 0.5%.
Using realistic borrow costs should reduce the attractive leverage that the optimizer finds
in pre-2009 folds, potentially reducing overfitting.

**Implementation:** Load FEDFUNDS data (or proxy), compute realistic_borrow = FEDFUNDS/100 +
0.005 per day. Replace fixed 0.005/252 in apply_vol_leverage with realized historical rates.

**Data note:** FRED FEDFUNDS data is publicly available. If not in the parquet store, use
a simple step-function approximation: 5.5% pre-2007, 0.25% 2009-2015, 0.5% 2016-2019,
0.1% 2020-2022 (from memory of historical rates).

**Success criteria:** KEEP if Sh_lev > 1.7 (small degradation from H559 is expected; purpose
is to test robustness). Falsification: realistic costs drop Sh_lev below 1.5 → H559's leverage
was partially an artifact of cheap capital assumptions.

## H570 — LeverageRegimeConditional (2-regime leverage)

**Signal:** Two-regime leverage: when SPY is above its 200d MA (bull), use cap=2.5×; when below
(bear), use cap=1.0× (no leverage). Lev-Sharpe objective.
**Hypothesis:** H559's vol-targeting de-risks when vol is high, but doesn't directly condition on
market regime. In bear markets (SPY below 200d MA), even low realized vol can precede major
drawdowns (e.g., slow grind down in 2000-2002). Cutting leverage to 1× in bear regimes avoids
this tail risk entirely.

**Risk:** This is a regime-switching overlay. CLAUDE.md history records that "regime switching
destroys value on mature MDR (H548: -0.073)." The difference here: this is LEVERAGE regime
switching, not portfolio weight regime switching. The portfolio stays constant; only leverage
changes. This should be more stable.

**Success criteria:** Sh_lev > 1.79 AND MaxDD_lev < -8% (better MaxDD than H559 at comparable
Sharpe). Falsification: cutting leverage in bear markets misses the TLT/GLD returns during
equity crashes that are H559's strong fold performance.
