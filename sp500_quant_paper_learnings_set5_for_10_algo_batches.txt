S&P 500 QUANT PAPER LEARNINGS - SET 5
Fifth non-overlapping set of 20 papers for planning 10 additional batches of trading algorithms

Purpose:
This file is a chatbot-ready research brief. It summarizes a fifth set of 20 quant trading,
financial modeling, machine-learning asset pricing, governance, ESG, text, crowd-sentiment, and
execution papers that were not used as core papers in Sets 1, 2, 3, or 4. It then turns those
papers into 10 practical development batches for S&P 500 strategy research in Claude Code CLI.

Important:
This is research and software-planning material, not financial advice. Every strategy must be
tested with point-in-time data, realistic transaction costs, conservative execution assumptions,
and strict out-of-sample validation.

================================================================================
HOW SET 5 IS DIFFERENT FROM SETS 1-4
================================================================================

Set 1 built the core alpha engine:
- momentum, trend, value, quality, profitability, defensive factors, PEAD, liquidity reversal,
  pairs/stat-arb, and ML ranking.

Set 2 added more anomaly and event signals:
- industry and residual momentum, reversals, seasonality, issuance, buybacks, analyst/insider/short
  signals, options-informed signals, attention, and sentiment.

Set 3 added harder-data signal families:
- lottery risk, distress, accounting sustainability, R&D/intangibles, customer-supplier links,
  volume/visibility, text tone, index events, fund-flow pressure, and cost survival.

Set 4 added the market and portfolio layer:
- equity premium prediction, forecast combinations, variance risk premium, option-implied risk,
  liquidity/funding stress, robust portfolio construction, and backtest governance.

Set 5 focuses on the research factory itself and richer modern signals:
- factor zoo reduction and anomaly decay
- q-factor and mispricing-factor controls
- machine-learning and nonlinear characteristic models
- IPCA/latent factor modeling
- no-arbitrage deep learning for asset pricing
- corporate governance and entrenchment
- employee satisfaction and human-capital intangibles
- sin stocks, carbon risk, and green return decomposition
- firm-specific news language and social/crowd opinion
- algorithmic trading and execution/liquidity effects

The main use of Set 5 is to make the strategy platform better at deciding:
- which characteristics are worth keeping
- whether ML adds real out-of-sample value
- whether an anomaly is just an omitted risk/factor exposure
- whether governance, climate, human-capital, and social/crowd data add incremental signal
- whether execution conditions should change trade aggressiveness

================================================================================
IMPLEMENTATION WARNINGS FOR THIS SET
================================================================================

1. Factor zoo work can explode in scope.
   Start with a registry of characteristics and a small canonical subset. Do not build 300 factors
   before you have timing tests, missingness reports, and out-of-sample evaluation.

2. ML models need stronger baselines than normal.
   Every ML model should be compared against:
   - equal-weight top-decile rank
   - linear model
   - elastic net
   - gradient boosting
   - simple factor-neutral rank

3. Alternative data needs timestamp discipline.
   Governance databases, employee-satisfaction lists, ESG data, carbon data, news, and social media
   often have publication delays or vendor backfills.

4. S&P 500 results may be weaker than all-stock results.
   Many anomaly papers get power from small, illiquid, or neglected names. For S&P 500, treat these
   signals as overlays, quality filters, or ensemble inputs unless standalone evidence is strong.

5. Text and social data can burn tokens quickly.
   Never paste raw news, filings, social posts, or article bodies into routine prompts. Cache compact
   feature tables first.

6. Execution is not a footnote.
   Algorithmic trading and liquidity papers should influence how the backtester models spreads,
   adverse selection, volume participation, and intraday execution windows.

01. Hou, Xue, and Zhang (2015)
Title: Digesting Anomalies: An Investment Approach
Source: https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2508322

Core idea:
The q-factor model, built around market, size, investment, and profitability factors, explains many
published anomalies. Investment and profitability are economically central return predictors.

Trading translation:
Use q-factor exposures as controls and as signal families. Before accepting a new alpha, ask whether
it is just investment/profitability exposure wearing a costume.

Features to implement:
- investment_to_assets
- ROE or profitability proxy
- q_factor_exposure_market
- q_factor_exposure_size
- q_factor_exposure_investment
- q_factor_exposure_profitability
- q_alpha_residual

Strategy ideas:
- q-factor baseline portfolio.
- Alpha residualization against q factors.
- Investment/profitability composite overlay for every value and quality model.

Main caveats:
- Factor construction choices matter.
- S&P 500 has less microcap anomaly exposure.
- Use q-factor controls as diagnostics, not as a magic truth model.

Source: https://academic.oup.com/rfs/article/30/4/1270/2965095

Core idea:
A model using market, size, and two composite mispricing factors can explain many anomalies better
than several standard alternatives.

Trading translation:
Create composite mispricing scores rather than treating every anomaly as independent. Mispricing
signals often cluster.

Features to implement:

- performance_related_mispricing_score
- composite_mispricing_rank
- mispricing_factor_exposure
- anomaly_cluster_id

Strategy ideas:
- Mispricing composite long/short research sleeve.
- Long-only avoid list for stocks with bad composite mispricing scores.
- Conflict engine: keep signals that survive mispricing-factor controls.

Main caveats:
- Requires mapping anomalies into coherent groups.
- Mispricing factors can become crowded.
- Composite construction must be fixed before backtesting.

03. Feng, Giglio, and Xiu (2020)
Title: Taming the Factor Zoo: A Test of New Factors
Source: https://ideas.repec.org/a/bla/jfinan/v75y2020i3p1327-1370.html

Core idea:
Many proposed factors do not add independent information once existing factors and multiple-testing
issues are handled. The paper provides a way to test new factors against a large existing factor set.

Trading translation:
Build a factor-admission gate. A new S&P 500 signal should not enter the production ensemble unless
it adds incremental value beyond existing signals and survives multiple-testing controls.

Features and controls to implement:
- candidate_factor_return
- existing_factor_exposure
- incremental_alpha
- factor_tstat_adjusted
- multiple_test_group_id
- factor_admission_status

Strategy ideas:
- Factor zoo triage dashboard.
- Signal admission test before adding features to the ensemble.
- Periodic pruning of redundant signals.

Main caveats:
- Testing too many variants still creates data mining risk.
- Incremental value can be regime-specific.
- Keep a record of rejected factors.

04. Green, Hand, and Zhang (2017)

Source: https://ideas.repec.org/a/oup/rfinst/v30y2017i12p4389-4436..html

When many characteristics are tested simultaneously and microcap/data-snooping issues are addressed,
only a smaller subset provides independent information, and post-2003 predictability weakens.

Trading translation:
For S&P 500 strategies, more characteristics are not automatically better. Use simultaneous feature
selection, post-2003 validation, and non-microcap relevance tests.

Features and controls to implement:

- microcap_dependency_flag
- feature_redundancy_group
- characteristic_decay_score

Strategy ideas:
- Characteristic pruning engine.
- Post-2003 robustness screen.
- S&P 500-only independent feature test.

Main caveats:
- A characteristic can be useful in an ensemble even if standalone alpha is weak.
- Avoid selecting features based on the full sample.
- Keep feature definitions frozen while testing.

Core idea:
A nonparametric method with adaptive group LASSO can select characteristics and estimate nonlinear
relationships between characteristics and expected returns.

Trading translation:
Many signals are not linear. A stock in the 95th percentile of a variable may behave differently
from a stock in the 70th percentile. Use nonlinear transformations and monotonicity checks.

Features and controls to implement:
- spline_transformed_characteristics
- nonlinear_feature_importance
- adaptive_group_lasso_selection
- partial_dependence_by_feature
- monotonicity_violation_flag

Strategy ideas:
- Nonlinear characteristic rank model.
- Feature shape diagnostics for each signal.
- Replace raw z-scores with learned percentile-shape scores.

Main caveats:
- Nonparametric models can overfit.
- Interpretability requires saved shape plots or compact shape summaries.
- Train only on past data in walk-forward windows.

================================================================================
NEW STRATEGY PRIMITIVES FROM SET 5
================================================================================

Primitive 1: Factor admission gate
- A new signal must add incremental value beyond existing factors and survive multiple-testing
  controls before it enters the ensemble.

Primitive 2: Characteristic registry
- Every characteristic needs a definition, source table, lag rule, missingness report, and decay
  score.

Primitive 3: Nonlinear characteristic scoring
- Replace raw z-scores with learned shape functions only after walk-forward validation.

Primitive 4: Shrunk expected returns
- Penalize unstable, high-dimensional forecasts and extreme portfolio weights.

Primitive 5: Latent factor diagnostics
- Use IPCA or related models to distinguish alpha from conditional risk exposure.

Primitive 6: ML with structure
- Deep learning should use economic constraints, macro states, and strong baselines.

Primitive 7: News-aware anomaly timing
- Some anomaly payoff is concentrated around news and earnings announcement windows.

Primitive 8: Alternative-data quality overlays
- Governance, human capital, carbon, green, and controversy features are slow-moving overlays.

Primitive 9: Crowd sentiment as conditional signal
- Social/crowd data should be author-weighted, timestamped, and often used for volatility/attention
  or earnings confirmation rather than raw return prediction.

Primitive 10: Execution-aware liquidity state
- Backtests need spread, adverse-selection, and intraday execution assumptions for rebalances.

BATCH 1: Factor Zoo Triage and Signal Admission
Source papers:
- Feng, Giglio, and Xiu (2020)
- Green, Hand, and Zhang (2017)
- McLean and Pontiff (2016)

Objective:
Create a signal admission system that prevents the strategy factory from adding redundant,
decayed, or overfit characteristics.

Algorithms:
1. Characteristic registry with lag rules and source definitions.
2. Incremental alpha test versus existing factor set.
3. Post-publication and recent-period decay score.
4. Signal admission status: accept, watch, reject, or risk-control-only.

Required data:
- Existing feature store.
- Existing strategy returns.
- Publication dates for academic signals.
- Monthly S&P 500 returns and benchmark factor returns.

Implementation tasks for Claude Code CLI:
- Build `src/research/characteristic_registry.py`.
- Build `src/research/factor_admission.py`.
- Create `configs/set5_batch1_factor_admission.yaml`.
- Save compact output to `results/set5_batch1_factor_admission_summary.json`.

Validation:
- Ensure rejected signals remain logged.
- Test pre-2003, post-2003, and post-publication periods separately.
- Report which signals add value after costs and after existing controls.

RECOMMENDED IMPLEMENTATION ORDER
================================================================================

1. Batch 1: Factor zoo triage and signal admission
Reason:
Before adding more features, build a gate that decides whether new features deserve to live.

2. Batch 2: q-factor and mispricing-factor controls
Reason:
You need to know whether new strategies are just old factor exposures.

3. Batch 10: Execution microstructure
Reason:
Cost assumptions affect every strategy, and S&P 500 strategies often look better than they trade.

4. Batch 3: Nonlinear characteristic model
Reason:
Gives better feature-shape diagnostics without jumping straight to deep learning.

5. Batch 5: Structured ML model ladder
Reason:
Only after simple nonlinear and shrinkage baselines exist.

6. Batch 4: IPCA latent factor model
Reason:
Useful for separating alpha from conditional risk, but more complex than basic controls.

7. Batch 6: News-aware anomaly timing
Reason:
Useful if you already have news and earnings dates.

8. Batch 7: Governance and human capital
Reason:
Slow-moving, useful overlays, but dependent on vendor/list data.

9. Batch 8: ESG, carbon, and controversy
Reason:
Valuable but requires careful industry normalization and data-lag handling.

10. Batch 9: Crowd/social opinion
Reason:
Interesting but noisy and data-platform dependent.
